# 赛题卡模板

设计草案 v0.1　·　纸面样题：[抢果蛇](snake.md) / [最低造价桥](bridge.md)

复制下面这张卡，为一个玩法写一页。读者有三位：写参赛脚本的人、负责跑比赛的人、只拿比赛记录做转播的人。

| 作者填写 | 需要让读者知道什么 |
|---|---|
| 题名、规则版本与看点 | [选手要达成什么？观众能看到哪个有代价的选择？] |
| 脚本怎样参赛 | [几个脚本同场？各自能看到什么？何时给出动作或交付方案？没有有效输出时比赛如何继续或结束？] |
| 规则与实例 | [哪些规则对每场都相同？列出一场可以手推的小实例，给全初始条件、参数和截止条件；有随机性时写清如何固定或记录抽取结果。] |
| 如何结算 | [写清判定顺序、结束条件及平局或同分的处理。优化题写清什么方案合格、在合格方案中比什么。] |
| 给选手的样例与给维护者的判例 | [给一组可照做的动作或方案和预期结果，再改一个会影响判断的选择，写出新结果及原因。] |
| 交给渲染器的比赛记录 | [除最终成绩外，列出重现这场比赛所需的初始状态或作品、实际发生的关键变化及其结果。] |

**维护约定。** 一份记录要能找到对应的规则版本、确切实例、参赛脚本版本和记录格式版本。换地图、河宽或载荷，可以沿用规则另建实例。改变碰撞顺序或成本算法，会改变对同一份提交的判定，应另标规则版本并保留旧判例。换画风时，用旧记录核对关键画面是否仍然讲述同一件事。限时创作、查阅资料、正式提交次数由每场比赛另行约定。

**纸面验收。** 把填好的卡给第二位读者。请对方遮住预期结果，独立算一遍，再只凭样例记录画出决定胜负的一帧。两个人算出不同答案，补规则；答案相同却画不出原因，补记录。正式办赛时，选手拿到对应版本的规则、可本地试跑的官方引擎或验证器和示例脚本，主办方收取参赛脚本后统一运行。
